5. 改一个 bit 即绕过 Windows 代码完整性：Project Zero 披露 .NET 加载逻辑缺陷

  • 评分：85
  • 来源： The Hacker News（原始研究：Google Project Zero）
  • 摘要： Google Project Zero 研究员 James Forshaw 披露，.NET Framework 4 在把文件作为可执行映像加载失败时会退回到"从内存中的普通副本运行"路径，该路径跳过映像校验，导致多道 Windows 防护被同一行为绕过。清除 .NET 文件头中的 IMAGE_FILE_EXECUTABLE_IMAGE 标志位这一个 bit，即可让 Windows 在启用 UMCI 的 Windows 11 S Mode 上加载未签名 .NET 程序集（CVE-2026-108398，CVSS 8.8，微软 10 月 13 日已修）；同样的加载行为也绕过了 Windows 主机上 VirtualBox 的进程加固（CVE-2026-87268，CVSS 7.8，Oracle 9 月已修，影响 7.2.16/7.2.18）。研究员还通过劫持 WerSecureFault.exe 加载的 COM 对象，无需管理员权限把测试代码注入最高保护级别的 PPL 进程——微软 10 月的修复未改变这一路径，该绕过目前没有独立 CVE。两项漏洞均为本地、低权限触发，并非远程拿下主机的通道。
  • 原文链接： https://thehackernews.com/2026/11/google-researcher-shows-how-single-bit.html
  • 评分理由： 单 bit 修改即穿透代码完整性与 PPL 隔离，研究新颖性极高；因需本地立足点且厂商均已补丁，实际受影响范围有限而降分。
